# AtomicDB Portable — Windows x64 Client & Central Management System

A self-contained, USB-portable Windows x64 distributed computing client for the AtomicDB/OpenBench chess-analysis network, accompanied by an enterprise-grade central administrator management platform with fleet monitoring, signed command dispatch, and live client simulation.

## 1. Overview & Core Concept

**AtomicDB Portable** enables contributors to provide computing power to the AtomicDB opening analysis and solving network directly from a USB drive without requiring prior Python installation, development tools, or administrator privileges on host machines.

The solution consists of two integrated components:
1. **Central Administrator Management Backend & Web Dashboard**: A web portal designed according to SaaS and monitoring console design guidelines. It acts as the command center for the software owner, providing real-time fleet health monitoring, thread/hash allocation management, remote lifecycle controls, and cryptographically signed command dispatch.
2. **AtomicDB Portable Windows x64 Client**: A Python-based desktop application (PySide6 GUI + headless mode) engineered for zero-dependency execution from USB. It features adaptive CPU/RAM allocation based on host load, SHA256 integrity verification of Atomic-Stockfish engine binaries, graceful process lifecycle management, and a strict local-override policy where host owners retain precedence over remote commands.

## 2. User Experience & Visual Design

The central administrator management dashboard provides a responsive interface with instant data updates and a dark slate palette:

### Key User Flows

1. **Fleet Overview & Health Monitoring**: The dashboard displays total active nodes, aggregate threads, total allocated hash memory, network throughput, and real-time node status tables with sorting and filtering.
2. **Device Enrollment Workflow**: The administrator clicks **Generate Enrollment Token**, specifies expiration and hardware policies (e.g. max allowed threads), and generates an authorization token. The portable USB client ingests this token to securely bind itself.
3. **Remote Control & Policy Dispatch**: The administrator selects one or multiple nodes to trigger `PAUSE`, `RESUME`, `UPDATE_CONFIG` (changing CPU mode or hash limits), or `REVOKE`. The actions are timestamped, signed with the admin secret, and queued for the node's next check-in.
4. **Interactive Client Simulator View**: An integrated live simulator inside the web console allows operators to preview and interact with the portable client's PySide6 interface, demonstrating adaptive core shifting, RAM hysteresis, and task reporting.

### Visual Identity & Theme

- **Aesthetic Direction**: High-density engineering console with clean typographic hierarchy, inspired by Bloomberg/Grafana telemetry suites.
- **Palette (60-30-10 Rule)**:
  - **Canvas (60%)**: Deep slate/charcoal backdrop (`#090D16` / `#0F172A`).
  - **Structural Surfaces (30%)**: Polished card surfaces (`#1E293B`) with hairline borders (`#334155`).

## 3. Key Product Decisions & Trade-Offs

- **Adaptive Resource Allocation Engine**:
  - *Chosen Approach*: Dynamic multi-tier monitoring evaluating system load every 5 seconds. If background user activity pushes host CPU utilization above 85%, the worker automatically steps down thread usage or pauses analysis using hysteresis buffers (requiring 3 consecutive stable cycles before scaling back up).
  - *Why*: Prevents host system lag or thermal throttling, ensuring host users never feel compelled to force-terminate the worker.
- **Local Control Precedence**:
  - *Chosen Approach*: The local GUI/system tray provides an immediate "Stop Analysis" button. If the host operator stops the software locally, remote `RESUME` commands are ignored until the local operator explicitly un-pauses.
  - *Why*: Respects host machine ownership, user privacy, and cybersecurity guidelines against covert or unauthorized compute hijacking.
- **PyInstaller Onedir Packaging with Relative Path Anchoring**:
  - *Chosen Approach*: All logs, engine binaries, cache, and configuration resolve strictly relative to `os.path.dirname(sys.executable)` (or `sys._MEIPASS` when frozen).
  - *Why*: Guarantees the application functions regardless of whether the USB mounts as `D:`, `E:`, or `F:`, and leaves zero temporary files on the host computer's `C:` drive.

### Component Structure & File Plan

- `src/`: Central administrator dashboard UI components (Fleet management, Node drawer, Command modal, Simulator, Audit log).
- `server/`: Express management backend implementing secure token enrollment, signed command queue, heartbeat ingestion, and audit log persistence.
- `AtomicDBPortable/`: Complete Windows x64 client source tree:
  - `src/main.py`: Entrypoint with CLI and GUI mode switches.
  - `src/gui.py`: Polished PySide6 GUI with dark styling and thread/memory monitors.
  - `src/worker_manager.py`: Process supervisor for `atomicdb_worker.py` handling stdout streaming, clean SIGINT/SIGTERM termination, and crash restarts.
  - `src/resource_manager.py`: Adaptive allocation engine calculating thread budgets and `hash + 300MB` RAM budgets with hysteresis.
  - `src/engine_manager.py`: Instruction-set detection (AVX2, AVX512, BMI2, SSE4.1) and SHA256 checksum verification.
  - `src/management_client.py`: Secure polling client with HMAC-SHA256 signature verification and nonce replay tracking.
  - `src/configuration.py`: Relocatable USB configuration serializer.
  - `src/security.py`: Token verification, nonce tracking, and credential handling.
  - `build.ps1`: Windows PowerShell automated packaging script for PyInstaller onedir distribution.
  - `tests/`: Automated unit and integration test suite covering allocation math, replay attacks, and process lifecycles.
